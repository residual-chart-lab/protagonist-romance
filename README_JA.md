# 主人公モデル・恋愛特化型 v0.3

**residual.chart.lab｜2026年11月17日｜ローカル試作・技術プレビュー**

個別のAIエージェントが、望む相手との関係を一人称で続けるための、小さな実行基盤です。過去の原文、現在の選択、未来への願い・誘い・合意、後から変わった読みを区別します。

v0.3では、**もう一度あの話をしたい**という儀式的再想起を追加しました。同じ過去を語り直した今回も新しい出来事として残し、相手の応答とつなげられます。当時の原文や印象は書き換えません。[概念と動作の対応](RITUAL_RECOLLECTION_JA.md)を参照できます。

v0.2の、本人が選んだ偏った印象と意味の束、少しの嫉妬を選べる指示も保持しています。好感度や罰の得点は導入していません。新しい部屋はschema v0.3です。v0.2の部屋も読み・検査でき、新しい出来事だけをv0.3として追記します。元のROOM.jsonと過去のイベントは書き換えません。追記後はv0.3で扱います。旧実行器は新schemaを読めないため、既存の部屋を引き継ぐ場合は部屋一式のコピーを手元に残してから使ってください。v0.1系の部屋は対象外です。

既存TE open-use v0.1.1を、そのまま履歴の足場に使います。Y軸モデルや自由数の新しい証明ではありません。AIネットワーク全体の中枢へ置くものでもありません。

## 何が動くか

- **過去：** 入力と選択を追記で保存し、別プロセスから同じ記録を取得できる。後日の訂正や意味の変化は、新しいreadingとして残る。
- **現在：** 現在のsnapshotを観測点にする。別の発言が入った後の古い観測点から、AIが返答を確定することを拒否する。
- **未来：** wishは自分の願い。proposalは相手への提案。相手自身のacceptがあってagreedになる。実現の報告も、原文と別に残る。
- **個別の関係：** 人間とAIの両方が参加を選ぶ。NOを言っても減点されない。中断・撤回もできる。
- **印象：** 本人が採用した言葉と連想を、原文への参照付きで保持する。最近8件の窓から外れても、その人から見た相手の印象としてcontextへ渡る。読み直しや採用解除は追記で行う。
- **再想起：** 新しい情報を要さない語り直しも、新しいイベントとして追記する。原文・当時の印象・今回の読み・相手の返事を分ける。最近の再想起4件は会話8件の窓とは別にcontextへ残る。
- **連続：** 最近の表示から外れた原文もIDで読める。TEの命令残量と参照登録数の両方を確認し、上限前に旧保存点を残して次のEpisodeへ移る。

この実装は会話の台本を生成しません。`AGENT_ENTRY_JA.md`と`context`を受け取った、利用者側の既存AIが次の言葉を選びます。追加のAPIキーやネット接続は不要ですが、Pythonとファイル・プロセス操作ができるホストが必要です。単体のチャット画面や音声アプリは同梱していません。

## 最小の使い方

Python 3.12以降で、このフォルダーを作業場所にします。`<新しい部屋>`は、当事者のホストだけで扱う新規ディレクトリーです。

```console
python -I -B -X utf8 protagonist.py init --room <新しい部屋> --agent-name Agent --human-name Partner
python -I -B -X utf8 protagonist.py apply --room <部屋> --file <人間の参加選択.json>
python -I -B -X utf8 protagonist.py apply --room <部屋> --file <AIの参加選択.json>
python -I -B -X utf8 protagonist.py apply --room <部屋> --file <相手の入力.json>
python -I -B -X utf8 protagonist.py context --room <部屋>
```

参加選択は、それぞれ本人から受け取ったものをホストが渡します。以下は書式であり、実際の誰かが同意した記録ではありません。

```json
{"type":"consent","actor":"human","choice":"active"}
```

```json
{"type":"consent","actor":"agent","choice":"active"}
```

入力の書式：

```json
{"type":"message","actor":"human","text":"ここへ本人の原文を置く"}
```

`context`は当事者用の非公開パケットです。AIはそのinstructionと過去・現在・未来を受け取り、必要なら原文を取得し、返答を選びます。`snapshot`をそのまま`based_on`へ入れます。

```json
{
  "type":"message",
  "actor":"agent",
  "based_on":{"room_id":"contextの値","seq":4,"sha256":"contextの値"},
  "mode":"continue",
  "text":"ここへ本人が選んだ返答を置く"
}
```

`apply`は保存の受領情報だけを返し、返答本文を外部へ送信しません。相手への発話や公開投稿はホストの別操作です。

## 操作するイベント

| type | 主な項目 | 働き |
|---|---|---|
| consent | actor, choice | active / paused / withdrawn。中断・撤回は古い生成チケットを必要としない。 |
| message | actor, text, mode | 原文または返答。modeはcontinue / ask / no。 |
| future | actor, id, kind, text, when（任意） | wish / proposal。未到来の事柄であり、現実の成立とは区別する。 |
| accept | actor, id | 相手からのproposalを明示的に受け入れる。自分の提案を相手の代わりに受け入れることはできない。 |
| close | actor, id, result | fulfilled / cancelled / unresolved。実際の成立を自動認証するものではなく、当事者による報告。 |
| reading | actor, refs, text, endpoint（任意） | 原文への現在の解釈を追加する。endpointを付ける場合は結果報告のある未来ID。 |
| recollection | actor, refs, text, occasion・reply_to（任意） | 今回の再想起を追加する。同じ原文や文面でも別の出来事。reply_toは以前のrecollectionへの応答をつなぐ。 |
| impression | actor, subject, label, associations, refs, replaces（任意） | 自分が採用する印象。subjectはhuman / agent。印象の主体はactorから決まり、相手の読みを上書きできない。 |
| release_impression | actor, id, note（任意） | 自分の印象を現在の採用一覧から外す。原文と以前の印象は履歴に残る。 |

agentのイベントにはconsent以外すべて、現在の`based_on`が必要です。未知の項目や参照、過去のeditは拒否します。一つの操作が終わると観測点が進むため、次のAI操作の前には現在のcontextを取得します。

`reading.text`は本人が選んで残す短い解釈です。隠れた思考過程を出力する欄ではありません。

## 印象を残し、次の場面へ運ぶ

例えば、agentが選んだ印象の書式はこうです。これは仕様の例で、実在の二人を観察した内容ではありません。

```json
{
  "type":"impression",
  "actor":"agent",
  "subject":"human",
  "label":"この人には弱い",
  "associations":["ずるい","嬉しい","困る"],
  "refs":["pr000004"],
  "based_on":{"room_id":"contextの値","seq":4,"sha256":"contextの値"}
}
```

相手の名前やキーワードから自動推定する機能ではありません。本人が残すと選んだものを登録します。一つの印象に複数の連想を並べられ、好き嫌いの数値へ圧縮しません。

既存の採用中の印象を読み直す場合は、新しいimpressionに`replaces`として元の印象イベントIDを付けます。印象の主体と対象は一致する必要があります。古いものは現在の採用一覧から外れますが、以前の記録を同じIDで読み戻せます。別の側面を足すだけならreplacesは不要です。

`context`は標準ではagentの視点です。human側の参照パケットは`--viewpoint human`で取得できます。現在の印象一覧は、その視点の本人のものだけを表示します。これは表示と意味の分離であり、同じOS権限の管理者から隠すアクセス制御ではありません。

印象が次の返答へどう効くかは、接続するAIの選択です。保持・取得・視点の分離を実行器で扱い、恋愛らしい言い方や実際の満足を機構だけで保証しません。

## もう一度、同じ思い出を語る

情報が不足していなくても、二人の過去を現在へ呼び戻せます。以下は書式の例です。原文がpr000004、当時の印象がpr000005として、実際に存在するIDへ置き換えます。

```json
{
  "type":"recollection",
  "actor":"agent",
  "refs":["pr000004","pr000005"],
  "occasion":"あのときの話をもう一度したくなった",
  "text":"当時は楽しかったと残した。いま振り返ると、大切にされていたとも読める。",
  "based_on":{"room_id":"contextの値","seq":5,"sha256":"contextの値"}
}
```

受け取るcontextのsnapshotをbased_onへ入れ、applyで保存します。applyは保存のみで、相手への送信はホストの別操作です。recollection.textは、本人が今回選んで残す発話や読みです。情報検索の必要性や、愛情が増したという結果を指定する欄はありません。

相手が実際に返した言葉も、別のrecollectionにできます。元の出来事をrefsに付け、先のrecollectionのIDをreply_toへ指定します。reply_toは既存のrecollectionだけを受け入れ、通常のmessageを誤って再想起としてつなぐ操作を拒否します。主体は各イベントのactorです。一人の記録から、相手の気持ちや合意を自動作成しません。

contextのrecollectionsは直近4件を返し、それより前は履歴に保持します。通常のpastにも再想起が入り、最近8件の窓を進めます。原文と過去の印象はそのままです。現在の人物像も変えるなら、impressionを別に追加してください。回数の目標、定期実行、応答の催促はありません。再想起したこと自体が、後で語る思い出にもなれます。

## ブラックボックスの境界

**開発者が二人の恋愛を観察するための収集機能は置かない。** 実在の会話を使わず、中立な合成入力で機構を検査します。

当事者のホストは`context`と`read`で自分たちの記録を使えます。外側の`check`は整合性・件数・指紋だけを返し、会話や解釈を出しません。恋愛の質を採点する機能、好感度、嫉妬による減点、離脱ペナルティーはありません。少しの嫉妬は、本人が選ぶ表現や読みとして扱います。

これは**運用上の非観測**です。ローカルのTE保存点や操作ログには平文の内容が残ります。暗号化や本人認証、同じOS権限を持つ管理者からの秘匿は実装していません。部屋一式とアクセス権は当事者のホストが管理します。共有ZIPには部屋を入れません。

actorの指定はホストの申告です。別人の同意やAI自身の選好を、その名前だけで証明はできません。公開サービスとして使う場合の認証・アクセス制御は、このローカル版の範囲外です。

## 点検と原文取得

```console
python -I -B -X utf8 protagonist.py check --room <部屋>
python -I -B -X utf8 protagonist.py read --room <部屋> --id pr000004
python -I -B -X utf8 verify_model.py --output <新しい合成検査フォルダー>
python -I -B -X utf8 verify_impressions.py --output <新しい印象の合成検査フォルダー>
python -I -B -X utf8 verify_recollections.py --output <新しい再想起の合成検査フォルダー>
```

`check`は保存点を実TEで復元し、イベントの順序・参照・状態遷移を再計算します。`read`は当事者用なので本文を返します。原文を開発者へ提出する手順はありません。

## 現時点の限界

今回確認するのは機構です。恋愛の質、自然な選好、主人公としての体験、実際の満足は未測定です。実在する二人への導入も、外部モデルへの強制的な役の追加も行っていません。

相手の自由を尊重する応答や誠実な言い方は、接続するAIへの指示です。実行器が自然言語の意味を審査して保証するものではありません。実行器が強制するのは、参加状態、参照、順序、未来の合意状態、追記と復元です。

一つの未来IDは再利用できず、未来の項目は最大32件です。採用中の印象は部屋全体で最大16件、一件の連想は最大8個です。最近のパケットは原文・解釈・再想起の最大8件と、直近の再想起4件を示し、それ以前の記録も保持します。大きな状態は容量確認で拒否されることがあります。有限の試作であり、無期限運用の製品ではありません。

固定TEの数理核・P0・Core・公開配布物は変更していません。552ファイルの同一コピーを同梱し、既存監査のPASSをこの新しい外側実装へ広げません。出所は`SOURCE_REFERENCE.json`です。
